Building a static website with Amazon S3 and Terraform

A clean test page for checking your S3 static website hosting, bucket policy, and uploaded HTML assets.

By Thanh June 2, 2026 6 min read

Overview

This article page is made to test a static website hosted on Amazon S3. It uses only HTML and CSS, so it can run without a server, build step, or JavaScript.

When the page loads from your S3 website endpoint, it means your bucket website configuration and object upload are working.

Static websites are a great first step for learning how cloud storage, permissions, and infrastructure as code fit together.

Terraform setup

In this lesson, Terraform creates the S3 bucket, enables website configuration, and attaches a bucket policy that allows visitors to read website files.

  • Bucket: stores static files such as HTML, CSS, images, and JavaScript.
  • Website configuration: defines the index and error documents.
  • Bucket policy: allows public read access for website objects.

Testing checklist

After applying Terraform, upload this file to the bucket and open it through the S3 static website endpoint.

  • The page should show the header, large title, image, article content, and sidebar.
  • The layout should become one column on mobile screens.
  • If you get access denied, check Block Public Access and the bucket policy.

Next steps

You can add an `index.html`, an `error.html`, and a small assets folder. Then use Terraform or AWS CLI to upload the whole folder into the S3 bucket.
